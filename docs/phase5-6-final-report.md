# 6. Awkward backend behaviour (max 10)

1. **Stale bulk response documented in frontend notes.** `docs/phase5-admin-frontend-notes.md` says updatedCount/skippedIds while backend returns updatedIds/skipped. Suggested fix: correct documentation to prevent contract regressions.
2. **Admin question summary requires a stat aggregate chain.** `QuestionService#getQuestions` performs multiple repository lookups for answers/reports; suggested fix: add a database projection or bounded batch query.
3. **Admin report threshold counts aggregate OPEN reports, not necessarily distinct students explicitly at the service layer.** `QuestionReportService#createReport` checks count and repository uniqueness should enforce a student/question pair; suggested fix: count distinct user IDs explicitly and expose that query in the repository.
4. **Study-session overview expiry mutates entity inside recommendation reads.** `RecommendationService#getOverview` saves ABANDONED sessions during a read method. Suggested fix: move expiration to scheduler/status calculator and never mutate in GET.
5. **Study-session effective status mixes wall-clock grace periods across multiple endpoints.** `StudySessionService`, `StudySessionSubmissionGuard`, and overview each calculate expiry differently. Suggested fix: centralize `effectiveStatus`, remaining seconds and grace boundary.
6. **Question-edit locking is enforced only through a 409, leaving the UI to infer which fields are editable.** Suggested fix: add explicit lock metadata (`answerCount`, `optionsLocked`, `immutableReason`) to detail responses.
7. **Question reports do not expose a current report status independently of report counts in result DTO.** `reportedByMe` is Boolean only; suggested fix: include reportId/status if the UI needs a richer state.
8. **Progress returns several state synonyms (`NO_QUESTIONS`, `NOT_ENOUGH_DATA`, frontend also accepts `INSUFFICIENT_DATA`).** Suggested fix: publish one canonical state enum and deprecate aliases.
9. **Optional analytics filters are numerous and have inconsistent null/default behavior across question endpoints.** Suggested fix: a typed filter DTO shared by chapter and system-wide endpoints.
10. **Pagination and error DTOs are not bundled in the frontend API types for every learning endpoint.** Suggested fix: generate or hand-maintain complete typed response schemas and a contract test suite.
